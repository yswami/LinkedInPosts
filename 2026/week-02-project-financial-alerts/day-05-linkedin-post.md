This week, our fictional Project Meridian moved through five very different questions.

1. Is the +$8M overrun real?
First validate actuals, pending labor, commitments, currency and forecast version.

2. Is it material enough to interrupt someone?
Apply governed policy—not a universal percentage—to decide whether to monitor, review or escalate.

3. Can we explain the uncertainty honestly?
Separate observed facts from planning scenarios, show what changes the range, and state the next human decision.

4. What is the portfolio blast radius?
The attractive local recovery moved risk to Project Beacon and shifted a $12M milestone into the next quarter.

5. What may the agent actually do?

This final question is where “agentic” becomes operational.

For Meridian, I would allow the agent to:

• reconcile and summarize evidence
• classify the signal using approved policy
• draft the explanation
• simulate recovery options
• assemble an approval packet

I would not let it independently:

• change the working forecast or baseline
• reassign shared resources
• move a contractual milestone
• commit or communicate a portfolio decision

Those actions need an authorized approver, transaction-specific validation, an audit trail and a recovery path.

The key distinction is not “AI versus human.”

It is reversible analysis versus consequential action.

Model confidence does not create decision authority.

The practical design pattern is:

VALIDATE → APPLY POLICY → EXPLAIN → SIMULATE → APPROVE → EXECUTE

The agent can do more as evidence, policy and controls become stronger—but autonomy should be granted per action, not through one global setting.
